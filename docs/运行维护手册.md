# ETF Research Lab 运行维护手册

本手册是本项目在多台电脑上启动、更新、训练和同步的唯一操作约定。项目的 `main` 分支包含代码、配置、静态数据和训练产物；任意电脑拉取同一提交后，应能直接查看同一版本的看板，而无需重新抓取或训练。

> 研究用途，不连接券商、不下单。本手册不记录或上传 API Key、账户凭据或 `.env`。

## 1. 约定与边界

### 1.1 远端必须同步的内容

每次“提交项目”或“上传项目”时，除代码外，还必须同步本次产生的静态文件：

- `data/market/`：日线行情；`data/intraday/`：QQQ、SOXX 5 分钟行情和清洗结果。
- `data/raw/`：宏观、新闻、地缘、央行、基本面等原始外部数据。
- `data/processed/` 与 `data/warehouse.duckdb`：特征和数据仓库。
- `artifacts/`：预测、评估、特征重要性、模型 Joblib、分钟回测、调参、集成与质量产物。

仅以下内容**不得**提交：`.env`、任何 API Key/Secret、账户信息、Python 缓存和临时文件。这些规则由 `.gitignore` 保护，但提交前仍须检查 `git status`。

### 1.2 多电脑协作原则

1. 把 `origin/main` 视为唯一共享事实来源。
2. 在抓数据、训练或轮询前，先执行 `git pull --ff-only origin main`。
3. 同一时间只在一台电脑执行“数据更新 + 训练 + 推送”流程；其他电脑只读、开发或等待同步。
4. Parquet、DuckDB、Joblib 是二进制文件，不能逐行合并。推送被拒绝时不要盲目 `git pull` 或强推；先保留本地状态，再选择远端版本或重新执行数据更新/训练。
5. 推送前跑质量检查，并把代码、配置、数据和产物作为同一个可复现快照提交。

## 2. 首次在新电脑启动

### 2.1 环境要求

- macOS/Linux（Windows 建议使用 WSL）。
- Python `3.11` 或 `3.12`。
- [uv](https://docs.astral.sh/uv/)。
- 可访问 GitHub 和外部数据源的网络。

### 2.2 克隆与依赖

```bash
git clone git@github.com:zaijianeric/trade.git
cd trade
git switch main
git pull --ff-only origin main
uv sync --extra dev
```

仓库已版本化的 `data/` 与 `artifacts/` 会一并被克隆。首次克隆后不要立即重新训练，先确认已有结果可读。

### 2.3 本地凭据

```bash
cp .env.example .env
```

在每台电脑本地填写 `.env`，绝不提交它。真实数据配置至少需要：

| 功能 | 必填变量 |
|---|---|
| Alpaca 日线与 5 分钟行情 | `ALPACA_API_KEY_ID`、`ALPACA_API_SECRET_KEY` |
| FRED/ALFRED 宏观与议息 | `FRED_API_KEY` |
| SEC 基本面（`live` 配置） | `SEC_USER_AGENT`，格式为 `姓名 邮箱` |
| 可选新闻补充 | `ALPHAVANTAGE_API_KEY` |
| 可选 LLM 解读 | `DEEPSEEK_API_KEY` 及相关 `DEEPSEEK_*` 变量 |

若没有 `SEC_USER_AGENT`，使用 `configs/free.toml`，或使用 `live` 配置逐类拉取除 `fundamental` 外的数据；全量 `live fetch` 会被 SEC 基本面源阻断。

### 2.4 启动与验收

```bash
# 查看已启用的外部数据源
uv run etf-mvp --config configs/live.toml sources

# 启动看板
ETF_MVP_CONFIG=configs/live.toml uv run streamlit run app.py
```

浏览器打开 Streamlit 地址后，确认：预测概览可读、行情页能显示日线、QQQ/SOXX 分钟模型产物存在。看板的“模型配置”可重新训练固定的 `1 / 3 / 5` 日模型。

## 3. 日常运行流程

### 3.1 每次开始工作前

```bash
git status
git pull --ff-only origin main
uv sync --extra dev
```

若 `git status` 非空，不要直接拉取。先完成、提交或妥善保存本机工作，避免把二进制数据产物混入其他电脑的更新。

### 3.2 刷新外部数据

具备完整凭据时，优先使用：

```bash
uv run etf-mvp --config configs/live.toml fetch
uv run etf-mvp --config configs/live.toml intraday-fetch --feed iex
```

第一条刷新日线行情、宏观、新闻、地缘、央行和基本面；第二条增量刷新 QQQ/SOXX 的 5 分钟行情并重建质量文件。

没有 SEC 身份标识时，按可用数据源逐类刷新：

```bash
uv run etf-mvp --config configs/live.toml fetch --kind market
uv run etf-mvp --config configs/live.toml fetch --kind macro
uv run etf-mvp --config configs/live.toml fetch --kind news
uv run etf-mvp --config configs/live.toml fetch --kind geopolitical
uv run etf-mvp --config configs/live.toml fetch --kind central_bank
uv run etf-mvp --config configs/live.toml intraday-fetch --feed iex
```

新闻源可能因 GDELT 限流或连接重试而变慢；Hybrid 提供方会回退到 Google News RSS 或保留可用来源，命令完成后再检查行数和最新日期。

### 3.3 训练日线模型

日线预测固定输出 `1 / 3 / 5` 个交易日。标准操作是启动看板，在“模型配置”选择“使用现有行情”后点击“并行训练 1 / 3 / 5 日模型”；该流程最多同时训练两个周期，并把结果汇总到 `artifacts/`。

```bash
ETF_MVP_CONFIG=configs/live.toml uv run streamlit run app.py
```

命令行 `train` 仍按配置文件的单一 `horizon_days` 训练，适合排查单周期或兼容旧流程：

```bash
uv run etf-mvp --config configs/live.toml train
```

不要在日线数据尚未刷新时训练。训练完成后检查：

- `artifacts/predictions.csv` 同时包含 `horizon_days` 为 `1`、`3`、`5` 的记录。
- `artifacts/metrics.json`、`artifacts/feature_importance.csv` 已更新。
- `artifacts/horizons/1d`、`3d`、`5d` 分别保留隔离的模型和特征产物。

### 3.4 分钟模型与盘中轮询

分钟模型仅用于 QQQ、SOXX。需要重新训练分钟模型时：

```bash
uv run etf-mvp --config configs/live.toml intraday-run --feed iex
```

美股交易时段启动轮询（默认每 300 秒）；它会拉取最新 5 分钟 K 线并滚动更新剩余日内预测：

```bash
uv run etf-mvp --config configs/live.toml intraday-poll --feed iex
```

用于 cron、launchd 或手动检查时执行单次：

```bash
uv run etf-mvp --config configs/live.toml intraday-poll --feed iex --once
```

轮询依赖当日分钟模型的 `forecast.csv` 与 `metrics.json`。若返回 `forecast_date_mismatch`，先运行 `intraday-run` 或 `intraday-train`，再启动轮询。非 NYSE 交易时段返回 `market_closed` 属正常行为。

## 4. 每日收尾与远端同步

完成数据刷新和训练后，在产出机器执行：

```bash
# 1. 检查代码、数据和产物是否都在变更列表中
git status

# 2. 验证代码质量
uv run pytest
uv run ruff check .

# 3. 建立可复现快照：包括 data/ 与 artifacts/
git add -A
git commit -m "data: refresh market data and model artifacts"

# 4. 上传唯一共享版本
git push origin main
```

提交信息应说明日期和动作，例如：

- `data: refresh external sources for 2026-10-30`
- `model: retrain 1d 3d 5d forecasts`
- `docs: update operating guide`

推送成功后，其他电脑只需：

```bash
git pull --ff-only origin main
```

即可获得相同数据、模型和看板结果。

## 5. 冲突与故障处理

### 5.1 推送被拒绝

说明远端已有另一台电脑的新提交。先停止本机更新，不要强推：

```bash
git status
git log --oneline --decorate -5
```

对于代码或 Markdown，可按普通 Git 冲突处理。对于 Parquet、DuckDB、Joblib、CSV/JSON 训练产物，应选择一台电脑作为本轮的产出机器：

1. 若远端版本是权威版本，丢弃本机未提交的派生产物，再 `git pull --ff-only`。
2. 若本机刚完成更完整的数据刷新/训练，先保存本机提交，再人工比较日期和训练时间；确认后以本机完整快照为准重新整理提交。
3. 无法确认时，保留两边信息并停止操作，避免覆盖较新的数据。

### 5.2 数据源失败

- **Alpaca**：检查 `ALPACA_API_KEY_ID`、`ALPACA_API_SECRET_KEY`、账户数据权限和 `feed=iex/sip`。
- **FRED**：检查 `FRED_API_KEY`；宏观数据会受发布时间影响，最新 `available_date` 晚于观测日是正常现象。
- **SEC**：补充 `SEC_USER_AGENT="姓名 邮箱"`；没有该变量时不要执行包含 `fundamental` 的完整 `live fetch`。
- **新闻**：GDELT/Google News 可能临时限流或断连；查看命令警告，保留上一次可用新闻数据并稍后重试。
- **分钟数据**：运行 `intraday-quality --feed iex` 重新审核质量；Basic 账户使用 IEX 且可能受最近数据延迟限制。

### 5.3 模型或看板异常

```bash
uv run etf-mvp --config configs/live.toml intraday-quality --feed iex
uv run pytest
uv run ruff check .
```

若 Streamlit 展示旧结果，停止并重新启动服务；日线模型重训后确认页面读取的 `artifacts/predictions.csv` 修改时间已更新。

## 6. 配置选择

| 配置 | 用途 | 说明 |
|---|---|---|
| `configs/default.toml` | 离线演示/测试 | 全部为合成数据，不需要网络或密钥。 |
| `configs/free.toml` | 免费真实数据运行 | Alpaca + FRED + Hybrid 新闻 + GPR；基本面默认关闭。 |
| `configs/live.toml` | 完整真实数据运行 | 包含 SEC 基本面；需配置全部必填凭据。 |

跨电脑统一使用 `configs/live.toml`（凭据完整时）。缺少 SEC 身份标识时临时使用 `free.toml`，但不要把不同配置训练得到的产物混在同一轮提交中。

## 7. 发布前检查清单

- [ ] 已在更新前 `git pull --ff-only origin main`。
- [ ] `.env` 未出现在 `git status` 中。
- [ ] 外部数据刷新完成，或已记录失败的数据源和原因。
- [ ] 日线 `1/3/5` 日预测与分钟产物已按需要训练。
- [ ] `uv run pytest` 与 `uv run ruff check .` 通过。
- [ ] `git status` 包含本次应同步的 `data/` 和 `artifacts/` 变更。
- [ ] 已提交并推送至 `origin/main`。
